# OpenNebula 執行需求（依據專案內容檢查）

本文件依照此 repo 內的建置腳本與套件宣告，整理出執行所需的環境。

## 短結論

不行。若要跑完整 OpenNebula，只有 Node.js 不足。

## 情境 A：只跑 FireEdge

若你只想建置或執行 FireEdge（位於 src/fireedge 的 UI/API 前端）：

### 必要條件

- Node.js（版本條件：>=10.21.0）
- npm

### 依據

- Node 版本要求：src/fireedge/package.json
- 建置腳本使用 npm 安裝與建置：src/fireedge/build.sh

### 備註

- 建置腳本包含 OpenSSL legacy-provider 相容處理（OPENSSL_CONF、NODE_OPTIONS）。
- 腳本的主要流程：
  - npm i --production
  - npm run build

## 情境 B：跑完整 OpenNebula（從原始碼）

若要從此 repo 建置並執行完整平台，還需要其他語言與原生依賴。

### 核心建置工具鏈

- Python 3（SCons 以 Python 為基礎）
- SCons
- C/C++ 工具鏈（gcc、g++、linker、make 相關工具）
- pkg-config

### 系統函式庫 / 開發套件

- libxml2 開發工具（xml2-config）
- xmlrpc-c 開發工具（xmlrpc-c-config 或等效的 pkg-config 模組）
- sqlite3 開發函式庫
- 若啟用 MySQL 建置選項，需 MySQL 開發函式庫（mysqlclient + mysql_config）

### gRPC / Protobuf 相關

- gRPC C++ 與 protobuf 開發套件（透過 pkg-config 取得 grpc++、protobuf）
- 在 gRPC codegen 流程會用到 protoc 與 grpc_cpp_plugin
- 若要產生 Go bindings，還需 protoc-gen-go 與 protoc-gen-go-grpc

### 專案中使用到的語言元件

- Ruby + Bundler/gems（用於 cloud/flow/form/CLI 元件）
- Python OCA/pyone 套件環境（src/oca/python/pyproject.toml，Python >=3.9）

## Repo 內證據位置

- 主建置系統與外部依賴檢查：SConstruct
- gRPC/proto 產生細節：src/rm/SConstruct
- FireEdge 的 Node 需求與建置：src/fireedge/package.json、src/fireedge/build.sh
- Ruby gems 與功能分組：share/install_gems/Gemfile
- Python OCA 需求：src/oca/python/pyproject.toml

## 實務結論

- 只跑 FireEdge：Node.js + npm 可完成 FireEdge 資產建置。
- 跑完整 OpenNebula：需要多語言與原生建置依賴（Python/SCons、C/C++、XMLRPC/libxml2、gRPC/protobuf、Ruby 生態，以及可選的資料庫開發套件）。
